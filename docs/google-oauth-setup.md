# 구글 로그인 설정 안내

이 사이트의 로그인은 구글 계정 하나만 사용합니다.
구글 OAuth 클라이언트는 **Google Cloud Console에서 직접 발급**받아야 합니다.
아래 절차를 따라 클라이언트 ID와 시크릿을 만든 뒤 전달해 주시면 Supabase 설정은 대신 넣어 드립니다.

소요 시간은 5~10분입니다.

---

## 1. Google Cloud 프로젝트 준비

1. <https://console.cloud.google.com/> 접속
2. 상단 프로젝트 선택기 → **새 프로젝트**
3. 이름은 아무거나 (예: `mywebsite`) → **만들기**

이미 쓰던 프로젝트가 있으면 그걸 골라도 됩니다.

## 2. 브랜드(동의 화면) 설정

좌측 메뉴에서 **API 및 서비스 → OAuth 동의 화면**으로 이동합니다.

1. User Type은 **외부(External)** 선택 → 만들기
2. 필수 항목만 채웁니다
   - 앱 이름: 사용자가 구글 로그인 화면에서 보게 될 이름
   - 사용자 지원 이메일: 본인 이메일
   - 개발자 연락처 이메일: 본인 이메일
3. 범위(Scopes)는 **추가하지 않고** 넘어갑니다
   기본으로 들어오는 이메일·프로필만으로 충분합니다.
4. 테스트 사용자에 **로그인 테스트에 쓸 본인 구글 계정**을 추가합니다

> 앱이 "테스트" 상태면 여기 등록한 계정만 로그인할 수 있습니다.
> 개발 중에는 이대로 두는 편이 낫고, 실제 공개할 때 게시 상태로 바꾸면 됩니다.

## 3. OAuth 클라이언트 ID 만들기

**API 및 서비스 → 사용자 인증 정보 → 사용자 인증 정보 만들기 → OAuth 클라이언트 ID**

- 애플리케이션 유형: **웹 애플리케이션**
- 이름: 아무거나 (예: `mywebsite-web`)

아래 두 값을 **정확히 그대로** 넣습니다. 오타가 있으면 로그인 시 `redirect_uri_mismatch` 오류가 납니다.

**승인된 JavaScript 원본**

```
http://localhost:3000
```

**승인된 리디렉션 URI**

```
https://swtmrbfkiwzixottysbv.supabase.co/auth/v1/callback
```

> 리디렉션 URI는 이 사이트 주소가 아니라 **Supabase 주소**입니다.
> 구글이 Supabase로 먼저 보내고, Supabase가 다시 우리 사이트로 돌려보내는 구조이기 때문입니다.

**만들기**를 누르면 클라이언트 ID와 클라이언트 보안 비밀번호가 나옵니다.

## 4. 전달

다음 두 값을 알려주세요. Supabase 프로바이더 활성화는 대신 처리합니다.

```
클라이언트 ID     : ...apps.googleusercontent.com
클라이언트 시크릿 : GOCSPX-...
```

직접 하고 싶으시면 Supabase 대시보드에서도 됩니다.
**Authentication → Sign In / Providers → Google** 에서 Google을 켜고 두 값을 넣은 뒤 저장하면 됩니다.

---

## 나중에 실제 도메인에 배포할 때

배포 주소가 생기면 세 곳을 함께 고쳐야 합니다. 하나라도 빠지면 로그인이 실패합니다.

1. **구글 콘솔** — 승인된 JavaScript 원본에 배포 주소 추가
2. **Supabase → Authentication → URL Configuration**
   - Site URL을 배포 주소로 변경
   - Redirect URLs에 `https://<배포주소>/**` 추가
3. 로컬에서도 계속 테스트하려면 기존 `http://localhost:3000` 항목은 **지우지 말고 함께 둡니다**

---

## 자주 겪는 오류

| 증상 | 원인과 해결 |
|---|---|
| `redirect_uri_mismatch` | 3단계의 리디렉션 URI 오타. 끝의 `/auth/v1/callback` 까지 정확히 일치해야 합니다 |
| `이 앱은 차단되었습니다` | 2단계의 테스트 사용자에 로그인하려는 계정이 없습니다 |
| `구글 로그인이 아직 설정되지 않았습니다` | Supabase에서 Google 프로바이더가 꺼져 있습니다 |
| 로그인 후 홈으로 튕김 | Supabase Redirect URLs에 `http://localhost:3000/**` 가 없습니다 |
| `file:///` 로 열었더니 동작 안 함 | OAuth는 `http://` 로 서빙해야 합니다. 아래 실행 방법을 보세요 |

---

## 로컬 실행

프로젝트 폴더에서 아래 명령을 실행한 뒤 <http://localhost:3000> 으로 접속합니다.

```bash
npx serve . -l 3000
```

포트는 반드시 **3000**이어야 합니다. Supabase Site URL과 구글 승인 원본이 그 주소로 등록되어 있습니다.

### serve.json 을 지우지 마세요

프로젝트 루트의 `serve.json` 은 `cleanUrls` 를 꺼 둡니다.

`serve` 는 기본적으로 `/auth-callback.html` 을 `/auth-callback` 으로 301 리디렉션하는데,
**이때 쿼리 문자열이 사라집니다.** 구글이 돌려주는 인가 코드가 바로 그 쿼리에 실려 오므로,
설정이 없으면 로그인은 매번 "로그인 정보를 확인하지 못했습니다" 로 끝납니다.

> 이미 한 번 잘못된 리디렉션을 겪은 브라우저는 301 을 영구 캐시합니다.
> 증상이 남아 있으면 강력 새로고침(Ctrl+Shift+R) 하거나 해당 사이트 데이터를 지우세요.
